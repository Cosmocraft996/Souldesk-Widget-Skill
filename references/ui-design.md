# SoulDesk 组件 UI 设计参考

新建组件默认参考 A「清晰均衡」。以下数值和样式是设计起点，可按组件内容、目标尺寸、可读性和用户偏好调整。各组件保留自己的配色，界面验收以已确认的方案为准。

| 项目 | 默认参考 |
| --- | --- |
| 字号 | 标题 16 px、正文 13 px、辅助文字 11 px。计数等主要数字可从 20 px 起，按信息重要性调整。 |
| 间距 | 4 / 8 / 12 / 16 px。4 px 用于紧密元素，8 px 用于控件或同行间隔，12 px 用于组件内边距，16 px 用于较明显的分组。 |
| 圆角 | 组件外框 14 px，按钮、输入框等控件 8 px。 |
| 控件 | 按钮与输入框最小高度参考 30 px，共用圆角。主要操作清晰可见，次要操作降低强调。键盘焦点可用 2 px 描边，禁用状态保持文字可读。 |

## 主题与尺寸

- 用 CSS 自定义属性管理组件内的背景、正文、辅助文字、强调色、边框、焦点色和错误色，按用途命名。搭配组件自己的配色时，检查文字与背景、控件与焦点的可辨性。关键信息用文字或形状配合颜色表达。
- 按默认尺寸和最小尺寸设计，窄版优先保留核心信息和主要操作，次要信息可换行、折叠或放入详情。内容铺满组件视口，适配桌面和侧边面板，通用浮动工具栏由宿主管理。

## 宿主控件避让

桌面和侧边面板共用宿主浮动控件。鼠标移入、宿主控件获得键盘焦点或「更多功能」菜单打开时，控件会显示在组件内容上方。按控件已出现的状态排版，让标题、关键数值、焦点轮廓和点击热区避开宿主控件，显隐前后保持布局稳定。

下表以 0.5.6 的左对齐布局修订为例，尺寸为从视口边缘起算的 CSS 像素参考。设计前按目标宿主的 `src/WidgetSurface.tsx` 和 `src/style.css` 核对实际位置。

| 宿主控件 | 避让位置 |
| --- | --- |
| 拖动按钮与工具栏 | 左上角先是拖动按钮，工具栏紧随其后。普通宽度预留约 176 × 36 px，组件宽度小于 260 px 时预留约 120 × 36 px，覆盖窄版收纳后的控件。 |
| 「更多功能」弹层 | 沿工具栏左边缘向下展开，左上角约距视口左、上各 35 px。按实际菜单宽高检查展开态，组件自身菜单优先从右侧或内容区中部展开，主要操作尽量放在宿主弹层覆盖范围之外。 |
| 缩放按钮 | 右下角距右、下边各 5 px，按钮约 22 × 22 px。预留约 32 × 32 px，尤其留意底部保存按钮、滚动到底时的列表操作和组件自身的拖拽手柄。 |

背景可以铺满视口，常驻避让集中在控件热区。顶部空间充足时，组件设置可放在右上角，窄卡片可把标题和主要操作移到下一行。底部按钮可以左移或抬高，为右下缩放留出空间。

用默认尺寸和最小尺寸检查桌面及侧边面板，跨越窄版断点的组件再检查断点两侧。分别触发悬停、键盘聚焦及「更多功能」展开，检查文字、焦点轮廓和主要操作是否被盖住，并实测宿主拖动、缩放与组件操作能否正常使用。

## 界面状态

- **加载**。首次读取可用骨架或简短提示保留布局。已有数据时，刷新可保留原内容并显示轻量的更新提示。
- **空白**。读取成功且确实无内容时，说明当前状态，并在适用时提供一个下一步，如「新建」或「清除筛选」。
- **错误**。说明失败的操作及可采取的下一步。可恢复时提供重试，有旧数据时可保留并标记其状态。重试过程中避免重复提交。需要登录或补充配置时，按实际原因给出入口。

主题变量与尺寸适配参考 [WidgetJS 主题手册](https://github.com/widget-js/skills/blob/master/widget/references/09-widget-theme.md) 和[新建组件手册](https://github.com/widget-js/skills/blob/master/widget/references/02-new-widget.md)。状态区分参考 [Kepo 插件开发 Skill](https://github.com/Enivel/kepo-plugin-dev-skill/blob/main/skills/kepo-plugin-dev/SKILL.md) 的界面规则。
